## STEPS, IN ORDER

You have no tools in this step. The graph has already listed the week folder and read it; the lines you may cite are given below the sources list, each after its reference in square brackets, grouped by file in file order. A line not given here cannot be cited.

1. **Read the sources list and the lines.** The sources list gives the week ending date and the latest tracker run id, which decide what "this week" means, the files declined as confidential, and every file in the folder.
2. **Look for a disagreement before drafting.** An action id that appears in a document line with a date different from its tracker due date is a disagreement. Return a stop with reason `disagreement` naming both sources and both values. The brief carries both values with both references in What needs a decision, and that action appears nowhere else on the page: not in What is due, not even with both dates.
3. **Draft the five sections, one sentence per source item, in the fixed shape below.** Write nothing else: no summary sentence, no connective sentence, no sentence about a row held or a file title. The shape is what the reader scans.
4. **Claim exactly what the sentence carries.** Every value you claim must be written in the sentence, and everything checkable in the sentence must be claimed: every number (also a number written as a word, two upward, claimed with the word as its value: "three"), every date, every action id, every person's or company's name (any two capitalised words count as a name), every quoted phrase. A sentence that misses one either way is removed whole. Write no run id, answer id or reference into the text; the code appends the references.
5. **Return the stops and the sentences together, once.** `stops` holds one entry per gate that applies (reasons below), each with the reason and one or two sentences naming the sources; the graph records each with the server's `stop` tool. `sentences` is one list: each sentence carries its `section` (one of the five keys below), its `text` and its `claims`, in the order the section reads; a section with nothing to cite has no sentence. Every claim carries all eight fields (`kind`, `ref`, `value`, `metric`, `new_ref`, `new_value`, `old_ref`, `old_value`); leave the ones its kind does not use as empty strings, so a `change` claim leaves `ref` and `value` empty and every other kind leaves the five change fields empty. Every claim carries its reference: `ref` for every kind but `change`, and `new_ref` and `old_ref` for a `change` claim, the one claim whose `ref` is empty; a claim with an empty reference is removed with its sentence. The graph turns the list into the five sections below and submits them with `draft_brief` once. Where this file says "call `stop`", return a stop in `stops`.
